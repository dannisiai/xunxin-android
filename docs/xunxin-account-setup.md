# 寻信邮箱账号部署

本地默认单机模式会直接进入，不发送验证码；只有部署和配置好后才启用邮箱账号。账号数据存储在自己的 Supabase 项目，验证码通过 Resend 发送。

1. 新建自己的 Supabase 项目，依次在 SQL Editor 执行 `docs/account-supabase.sql` 和 `docs/xunxin-email-auth.sql`。已有项目同样需要执行两个脚本来升级。保留既有数据，先备份再升级。
2. 在 Resend 配置并验证你自己的发信域名，创建 API Key。使用这个域名下的发信地址。
3. 在部署平台的服务端环境变量中设置：
   - `NEXT_PUBLIC_SELF_HOSTED_MODE=false`（修改后需重新构建）；
   - `SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY`；
   - `RESEND_API_KEY` 和 `REALITY_BRIDGE_EMAIL_FROM`（例如 `寻信 <hello@已验证的域名>`）；
   - `XUNXIN_EMAIL_CODE_SECRET` 和 `ACCOUNT_GATE_SECRET`，分别使用独立的随机长字符串，前者至少 32 位。
4. 重新部署后用真实邮箱测试注册、验证码登录、可选密码登录、退出和失效验证码。确保通过 HTTPS 访问；不要将 service role、邮件 API Key 或密钥放入 `NEXT_PUBLIC_` 变量或提交到 Git。

验证码 10 分钟有效，最多尝试 5 次，同一邮箱和用途至少间隔 60 秒，同一来源一小时最多请求 20 次。部署平台应正确设置可信的客户端 IP 转发头，并配合平台的请求限速；密码登录的现有限速是单实例内存限速，多实例上线前需使用共享限速或网关防护。

## 数据范围

此功能提供云端账号和会话，不会自动把聊天记录、角色卡等本地数据上传，也不保证不同账户在同一浏览器上的本地资料隔离。当前本地数据库按浏览器而非账号保存；多人共用一台设备时应使用各自独立的浏览器用户配置文件。要支持同一浏览器安全切换账号，需要另行改造本地存储和备份；跨设备同步也需要单独配置并验证。上线前应先解决这些问题，再对用户作出资料隔离或云同步承诺。
